## 产品边界（须保留）

- 主要闭环严格限定：**日程、真人感、私聊、记忆宫殿、查手机、主动消息**。
- 查手机查看的是 **Char 自己的手机**；Char↔NPC 手机微信和 Char→User 主动消息不是同一收件人/通道。
- 主功能既有的手动/自动选择应当保留；次要应用不得强制自动化。
- 不增加第二套自主生活引擎，不复制参考 MarshmallowMachine APK 的源码或 UI。
- 优先修复已有数据链上的断点，保持用户的原数据、开关值和单项手动生成入口。

## 证实的问题及本批次边界

1. **设置实际含义与入口不一致（已补小范围闸门）**：
   `OSContext.tsx` 中生活事件监听曾对来源为非 phone 的事件设置 `budgeted: false`，可以绕过“独立后台 AI 请求”预算；`tick` 与动态互动监听也未全部在入口处核对“Char 手机自主生活”总开关。
   现在统一在事件驱动的**手机自主 AI 生成**、前台调度及朋友圈互动触发点核对原有开关，并让事件驱动的备忘录/朋友圈决策遵循共享预算。**事件保存、AMSG 上下文刷新、记忆宫殿归档仍先执行，不受这道 AI 生成闸门限制**。
2. **请求生命周期不一致（已局部修复）**：
   `characterPhoneAiRequest.ts` 已有 150 秒保护和后台熔断，但 `characterMemoAutonomy.ts` 与 `characterMomentAutonomy.ts` 自己设了 60 秒 `AbortSignal.timeout` 且绕过共同请求封装。本批改为共用该封装，不改模型/提示词/保存合同，不自动重试；仍保留必要超时，不宣称已彻底解决慢请求。
3. **失败语义不清（已局部修复）**：
   共享请求将“客户端等待上限”“主动取消”“网络连接中断”区分说明；服务端是否继续处理 **未知**，不误报服务端失败，不自动重发。
4. **设置文案语义歧义（已澄清，不更改原行为）**：
   `readPhoneInboxPreferences().autoFullWeChat` 实际选择前台自主任务的优先轮换列表；关闭它之后，既有 `wechat` 任务仍存在于默认列表，不能把该开关解释成“禁用全部微信自动更新”。已仅修改 `CharacterPhone.tsx` 提示文案，保留设置值、默认行为、自动与手动入口。
5. **手动批量微信的有效结果被全盘跳过（已做有界修复）**：
   `CharacterPhone.tsx` 的 `generateInbox(false, true)` 原来在 `incoming.length===0` 时直接抛错，尚未执行已有的支付收据、NPC/Char 朋友圈存储。现在 fullSuite 允许无新增微信但其他子结果有效：逐项写回已有数据、追踪实际新增数；无任何可保存结果才提示失败，旧记录不清空。非 fullSuite 的单项微信入口仍坚持“至少一个有效会话”。全套按钮改为回报实际新增会话/其他项数，未调用时不谎称成功；**该修复还需 API 异常/真实 UI 测试**。
6. **其余不作不实判断**：
   `CharacterPhone.tsx` 已有设置搜索、折叠分组、原有单项生成和一次生成微信全套按钮。本轮没有删除功能或重排 UI。其实际卡手程度、手机浏览切页与存档重载都 **待实操**。
7. **更深的调度协作仍未完成**：
   现有前台手机 tick 与 AMSG 云端任务相互独立。以后只能在实测证据支持时复用现有任务/时间上下文，不能直接合并收件人渠道或改变云端任务。

## 2026-10-28 续修记录（PR #15）

- **事件来源不应改变手机 API 的配置**：`context/OSContext.tsx` 中 Char 手机自主消费事件时统一使用 `resolveCharacterPhoneApi(charId, baseApi)`；`amsg2` 和其他生活事件只是触发依据，不代表可以绕开手机独立 API。AMSG 本身的发送渠道没有改动。
- **朋友圈决策的无效预算占用**：`utils/characterMomentAutonomy.ts` 将 `reservePhoneApiBudget` 移至现有上下文、日程读取之后且实际请求之前。避免在本地准备失败时提前占用可付费调用预算；仍保留既有决定间隔。
- **手动“微信全套”局部失败恢复**：`components/chat/CharacterPhone.tsx` 对 fullSuite 容忍缺失的 threads 数组，只尝试保存已经能验证的其他子结果；如果微信存储失败，不再假称会话已写入，也不记录虚假的新增联系人或聊天生活事件。其他可用的朋友圈/支付结果继续按既有存储方法写入。非 fullSuite 的旧逻辑不改。
- **设置降低理解门槛**：在搜索框下方展示已存在开关对应的“当前使用方式”，不增加开关，也不改用户存储的设置值。
- **明确新增回归测试**：`utils/characterPhoneAutonomy.test.ts` 增加两个“手机自主生活关停 / 独立后台 API 关停”测试，用已有存储及 mock API 验证不消耗请求额度。
- **无部署的 PR 验证**：`.github/workflows/phone-life-pr-regression.yml` 对目标开发分支的 PR 使用 Node 22 / pnpm 9，运行既有核心电话、生活事件等 Vitest 用例及完整 `pnpm run build`；不会部署、不会碰云端 Worker 或 master。**只有工作流真实完成才能填写通过或失败结论**。

这轮的剩余主要风险：多次异步手机保存之间的恢复与重复计费仍要模拟慢响应、存储失败、重载和角色切换。真实设备操作体验仍未验收；如 GitHub CI 失败，须留在 Draft PR 修复，不准合并。

## 2026-10-28 继续修复：用生活动机驱动 API 档位（本 PR）

- **不把时间配额当成触发器**：新增轻量的 `utils/characterPhoneOpportunity.ts`，只从已有联系人、微信消息和 `characterLifeEvents` 判断未回复 NPC 消息或最近 12 小时内已确认的非手机生活事件（AMSG 发给 User 的已保存事件、现实活动和购买）。仅有定时器到点、预设日程计划、无关通知或者旧事件，不能构成独立手机请求的理由。
- **不再随机轮换多个生成器**：`OSContext` 的三分钟 tick 仅检查机会；发现未回复 NPC 消息，只调用原有 NPC 自主微信；发现已确认的生活经历才在原有已开启的功能内依序寻找合法动作。朋友圈发布、备忘录和评论已有事件监听，不再在该 tick 中额外轮询生成。仍使用原控制器和原保存链路，不修改 AMSG 云端任务或发送给 User 的消息。
- **同一动机不重复花费**：只有调用确实占用了 API 额度才标记该事件已处理（包含上游状态不确定的超时）；本地跳过、忙碌、睡眠和额度不足不会消耗事件。利用仅存最近 100 个动机键的小型去重记录，而不是新建生活引擎、消息台账或第二套排程。
- **档位作用更加明确**：保留用户所有原有 `economy/balanced/active/custom` 配置数值；仅负责每日自主调用上限和调用间隔，不再意味着每隔一段时间就必须发生角色活动。手动请求、私聊与 AMSG 2.0 云端渠道原样保留。
- **设置减负**：原有页面保留搜索与折叠，增加“常用设置／更多设置”的轻量可视切换，原有选项完整保留，旧配置键和默认值不变。标注“最早允许再调用”不是角色计划发消息时刻。
- **回归覆盖**：`utils/characterPhoneOpportunity.test.ts` 覆盖空时钟 tick、已确认 AMSG 事件、单次标记、非手机生活事件、旧事件和未回复真实联系人优先；已加入原有无部署 PR CI 工作流。

**尚未完成／不得假称完成**：本轮未把整个自主生活调度搬进 AMSG Worker，也未将所有不同应用统一成一次 AI 返回合同（现有微信一键全套机制保留）。仍需等 PR CI 的真实结果、安卓端操作体验、角色多时区、设置切换和长响应中断后的完整验收，之后再决定是否进一步收敛调度。

## 2026-10-28 第三批续修：修正误触发、回复插队和迟到结果

1. **已有 NPC 未回复消息优先**：`runCharacterPhoneAutonomy` 复用原控制器新增 `replyOnly` 入口。当自主机会来自已保存的未回复 NPC 消息时，绝不先触发“通讯录不足四人”的新联系人初始化，也不能临时另开新话题。这样不会把“补联系人”错误计作“回复已发生的会话”。
2. **设置间的隐式副作用已取消**：调整“自动更新优先处理微信与朋友圈”只保存该优先级设置，不再背着 User 重新打开关闭过的“Char 手机自主生活”总开关。手动生成与其他开关不变。
3. **普通朋友圈存储操作不再触发 AI**：沿用原 `CHARACTER_MOMENTS_CHANGED` 事件，添加兼容的 `changeKind/actorId` 元数据；只有保存新动态或 User 新发表的评论允许进一步自主互动评估。点赞、撤销点赞、删除、清理、AI 自动评论、界面刷新仍可通知 UI 更新，但不会无意义地触发后台新请求。
4. **慢 API 返回前做最终状态校验**：自主微信生成后、入库前重新检查当前自主开关、后台许可、联系人是否仍在、是否有手动批量任务以及同会话的消息基线。若期间用户已回复、删除联系人或关闭开关，迟到结果只作跳过，不再重新污染或“复活”旧内容。已发出的请求仍照原预算记录，绝不自动重试。
5. **通讯录初始化不会在一轮内连花两次 API**：通讯录补建已经调用一次模型时，即使没有获得新联系人或请求失败，也结束当前自主任务，不再立刻接着调用另一个 NPC 对话生成器。已增加空联系人结果只发一次网络请求的回归用例。
6. **针对性回归**：在现有测试中增加少量联系人但已有未回复消息、纯回复机会无联系人初始化、操作过程中关停自主、手动抢先回复、朋友圈事件分类等测试。测试在草稿 PR 的非部署流水线执行，实际通过状态以 GitHub Actions 最后一次结果为准。

**未完成事项**：实际 Android 逐页体验、AMSG 云端任务时机与手机自主时间安排进一步协调、所有自动生成多任务的跨应用单次请求规范化、异步保存失败恢复与多角色跨天体验。此批只改现有执行细节，不改 AMSG Worker、人物持久化格式或手机应用自动/手动策略，不合并到开发分支或 master。

## 2026-10-28 第四批续修：防止慢请求“复活”已关停或清除的内容

- **实际风险**：后台朋友圈和自主备忘录的 AI 等待期间，User 可以关闭自主生活、关闭独立后台请求、清除手机生活事件、手工编辑笔记或者自己发一条新朋友圈；原流程在网络完成后没有统一复核这些变化，可能写回过时内容。
- **朋友圈**：复用既有 `isCharacterPhoneAutonomyEnabled` 与 `readPhoneAutonomyPreferences`，在启动、上下文准备之后、结果写入之前检查原开关；重新检查事件 ID 是否仍存在，拒绝在等待期间用户已发布新动态的迟到结果。原有事件去重及一条动态的保存逻辑不变。上下文准备失败不再提前占用六小时的自主决策间隔。
- **备忘录**：自动生成在发出请求前以及响应落库前核对开关、事件是否仍在真实事件记录内，以及原笔记快照是否被 User 改过；一旦不一致就舍弃迟到的结果，不能复活被清理内容或覆盖人工编辑。已发请求不会自动重试，手动备忘录生成不受后台开关约束。
- **有界回归**：新增 `utils/characterPhoneLateResult.test.ts`，涵盖请求中途关停、删除事件、新手写朋友圈、备忘录被手动修改/清空以及关闭自动后台后依然允许手动更新。该用例加入现有 PR 的非部署 CI；只以实际运行结果判定通过。

**仍未验收**：Android 实机长时间关闭/重进/跨角色、多时区、AMSG 云端触发、多应用一次返回的 API 使用体验。维持 Draft PR，不触及正式部署。

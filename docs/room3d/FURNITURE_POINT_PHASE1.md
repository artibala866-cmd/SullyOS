## 本批代码变更

- \`furniturePointRegistry.js\`：座位与床位结构检查；有限坐标、几何尺寸范围、重复 ID 与当前缺乏安全攀爬机制的高架床位校验；不把 bbox 中心当接触点。
- \`furnitureCapabilityRegistry.js\`：按**实际登记**的点位与原有动作能力映射登记“坐、躺、厨房、卫浴、镜子、电竞、餐桌、抱玩偶、浇水、冰箱”，不靠浏览分类或名字推断。
- \`seating.js\`、\`furnitureCatalog.js\`、\`furnitureInteractions.js\`：同一套经过基本验证的点位数据既用于预览标签、菜单，也用于动作定位；其他居民已有占位的槽位不继续提供给当前角色。
- \`editor.js\`：普通坐姿先取得座位入口、检查整段通路、走到入口；抵达时重新核验家具朝向/位置、占位和座位是否存在；二号骨骼角色调用原有坐下过渡，无安全入口时拒绝。床铺已有二号骨骼角色的安全入口规则不再通过失败后直接贴到床面规避。
- \`mirrorJourney.js\`：衣柜与镜子两点之间任何一段缺路就取消此次穿搭行程，不再静默瞬移。
- 四组回归测试：元数据全部覆盖、局部坐标旋转、占位菜单、高架床拦截、镜前行程，以及两款床尾凳 GLB 三角面射线采样。

3. **攀爬与上下铺**：\`bedroom_bunk\` 的 2 个床点与 \`bedroom_loft\` 的 1 个床点因没有连续进出方案暂不提供。没有删除其存档或原始目录记录。\`loft\` 另缺床点。
4. **尚有兼容路径**：本批主要修复二号骨骼角色；非骨骼旧人物的部分家具姿态仍使用原来的直接就位，未达到“完全不瞬移”标准。也没有解决所有厨房、卫浴、设备及双人家具组合的路径与 IK 问题。

目视回归至少包括：不同人物高度与宽度、正反 90/180/270° 朝向、同家具两人占用与错位抢座、不同房间行走、卧室床沿被挡住、家具调整/收纳后中断、连做坐下→起身→换座、镜子→衣柜被阻隔，以及手机/降低动态效果时的行为。

## 第三批：通用入座／占用中家具保护（本轮）

- **复查到的具体缺陷**：旧代码在电脑椅起身入口找不到时，只对 `gaming_chair` 额外尝试侧面站位；其它同能力椅子即使能坐，也可能无法正常起身。这是不应存在的型号硬编码。
- **实际修复**：`seatChange.js` 统一根据坐点位置、朝向生成前方与左右侧入口候选；设备座椅采用侧面路线，桌椅吸附座位优先侧面，避免从桌面直穿。`editor.js` 的玩家、NPC 自主互动及自动行动都调用这套入口机制，并保存本次实际安全进入站位；起身前重新核验可用性。仍未完成逐件 IK 碰撞画面校准，侧面动作的外观不能仅靠路径绿灯保证。
- **编辑阶段防瞬移**：`occupiedFurnitureChange` 在房间提交前检查各当前占用座位、床位的物品 ID、几何姿态及有无新摆件遮挡。有人使用时拒绝挪动、转向、收纳、删除、更换物品及覆盖臀部接触面，提示先起身；无关家具和仅改颜色仍可编辑。
- **设备阶段防瞬移**：`activeFurnitureDependencyChange` 防止正在使用的电脑、厨房设备、镜子、浇水对象及依赖家具被移动或收纳；只限制真正影响执行位置的几何字段。操作结束后可以正常编辑。
- **上下铺实模检查**：直接解析 `bedroom_bunk.glb`（4,104 三角面）和 `bedroom_loft.glb`（2,735 三角面），在原始 3 个床点 x/z 上采样床垫多层交点，校验所填高度与附近真实三角面接近（误差阈值 0.15）。**只通过了床面位置检验；未证明梯子和上下床动作安全**。这 3 个高床点依然不暴露为可互动选项。
- **防止下次重建覆盖修复**：`art/jellyfish-home/export_kit.py` 原先只保留 220 个外置资源，重新 Blender 导出时会抹去 28 个合并版资源的人工坐点。现保留 `sofa`、`chair`、`pouf` 等原资源既有 seats/beds 和互动能力元数据；重建时会输出需要重新审核接触点的提示，**保留数据不代替几何重新验证**。
- **回归**：增加椅子前后左右站位、挡住侧面时拒绝进入、旧电竞设备匹配、使用中家具编辑冲突、多人座位占用、第三方支持摆件穿模、卧室高低床几何及导出元数据持久化检查；流水线继续执行所有 Room3D 测试与完整构建。

## 第四批接手核实与 P0 闭环修复（2026-10-28）

本次先比对当前开发分支和原 Draft PR：修复分支比共同基点有 117 个提交，开发分支另有 7 个后续提交；两边都改过 `apps/room3d/editor.js`。因此 **保留在 Draft PR 修复分支内，不直接合并/覆盖开发分支的渲染、人物与时间修复**，之后必须以开发分支最新代码逐段对齐相关逻辑。

复核现有分工：
- `furniturePointRegistry.js` → `seating.js` → `furnitureInteractions.js` / `editor.js`：目录坐床点及原有动作玩家使用，仍沿用原坐床过渡播放器。
- `furnitureCapabilityRegistry.js` → `furnitureCatalog.js`：**目前仅负责目录能力索引与标签**，不是所有执行入口的统一分发器，不能把目录登记视为动作闭环。
- `furnitureStationRegistry.js` → `furnitureInteractions.js` / `editor.js`：设备活动站位的菜单与运行前校验；编辑提交复用占位和依赖物保护。原专用厨房/卫浴/电竞/镜子控制器未被替换。
- 回溯发现：`travelHistory()` 的撤销/重做直接替换房屋布局，未经过普通 `commit()` 的占位/运行设备保护；浇水执行直接设置 `visitorPlant` 后由 `placeVisitor()` 就位，缺少人物到达站位的导航过程。

本批更改：
1. **浇水入口**：在原 `wateringSpot()` 中增加可选的 `canReach` 导航过滤，允许跳过不可达的候选站位而不是立即传送；`editor.js` 的菜单、AI 家具动作候选与手动执行在能力判断时使用可达候选，真正执行时沿用 `walkTo()`，抵达后核实同一植物/站位有效才开始播放浇水。不中途切换到另一侧的站位；取消与结束后保留人物实际站立位置。
2. **撤销/重做保护**：`travelHistory()` 在弹出历史快照前调用现有 `occupiedFurnitureChange()`、`activeFurnitureDependencyChange()`，有坐躺中的人体、坐下/起身过渡或活跃设备依赖时，不允许造成几何突变。未另建占用表。
3. **回归测试**：增加 `apps/room3d/wateringReachability.test.js`（全路径拒绝、侧面回退、缺失/收纳物拒绝），并加入原 `.github/workflows/home3d-furniture-points.yml` 自动化脚本。

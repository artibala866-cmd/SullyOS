# 真人感输入结束接话：安全适配

参考文件：用户提供的 MarshmallowMachineNext-v0.1.0-next.61 APK 中 `chat/composer-interruption.js`、`chat/chat-composer-guard.js`、`chat/real-person-reply-timing.js` 和 `chat/pending-actions.js`。按其运行机制适配 SullyOS 消息、存储和生成流程，没有引入 APK 的第二套数据库、后台引擎或额外判断模型。

## 实际行为

- 私聊自动回答只由明确开启的真人感授权。历史普通自动回复配置只保留群聊用途，私聊设置不再提供重复开关。
- 真实发送成功才登记未回答消息，沿用现有连续消息合并、消息 ID 核对和跨窗口 Web Lock。导入历史、失败发送、音乐卡片不创建私聊回复任务。
- 使用输入结束模式。真实草稿、IME 组词、当前输入框的可见键盘会暂缓回复；收起键盘/结束输入后保留 2500ms 输入静默窗口。焦点本身不会永久锁住 Android 会话。短等待只合并当前发言，不能凭时间产生话题。
- 日程和注意力保留为上下文与角色状态，不用忙碌/睡眠计划阻断输入结束模式，也没有恢复随机几分钟的回复计时。
- 生成途中重新输入时，本地保留当前结果直到输入释放；若用户又真正发送了新消息，则按既有消息 ID 规则废弃旧轮、回答新轮。云端结果写回收件箱等待输入释放，不阻塞其他角色/明确提醒，不重新请求生成已有结果。
- 真人感关闭先撤销待办与授权代次，然后停止自动生成。不同角色、卸载后的生成、工具续轮、记忆召回/提取/向量化/整理继承同轮取消信号。重开不能使旧授权复活。已受理的云端自动回复按 UUID 停止，迟到内容受现有墓碑拦截；手动回复和明确提醒不随之取消。
- 群聊待回复使用独立持久键；真人感关闭不撤销群聊正在保存的发言。群聊原有输入偏好保留。

## 验证与限制

专项与相关回归覆盖私聊授权、输入静默、组词、键盘显示/隐藏事件、连续发言、关闭/重开、多个角色、云端迟到、收件暂缓、群聊隔离、记忆取消和现有音乐/学习室提醒。测试中的模型与云端请求使用模拟或离线拦截，不调用用户付费 API。

这些验证不能替代真实模型的自然度对照、Android 输入法真机，以及个人 Worker 的实际取消效果。已经发出的请求无法追溯撤销费用；远端取消失败时仍需依靠本地墓碑拒收迟到结果。

本次只迁移真实用户发言的自动接话及其取消、输入和派生调用边界。原有独立授权的日程生成、手机后台、学习室自动业务及 2.0 明确排程仍按原许可运行；新增每日自主联系/手机搭车的职责拆分仍见原关联审计，不能宣称已在本次整体迁移。

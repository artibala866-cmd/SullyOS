# 真人感、主动消息 2.0 与共用服务的职责

这份规范以用户最新要求为准，供棉花糖真人感的后续安全适配使用。这里明确区分**目标归属**与**现阶段已经实现的行为**，不能把整理文档、改名或删除入口当成移植完成。

## 用户可感知的目标边界

| 场景 | 目标归属 | 触发依据 |
|---|---|---|
| 用户发完消息，角色自然接话，无需按 AI 回复 | 真人感 | 真实发送成功且尚未回答的消息 |
| 合并连续消息、等待用户结束输入、热聊与忙碌时的接话判断 | 真人感 | 当前对话、输入状态与可信的日程事实 |
| 自然继续未结束话题、分享近况、按人设和上下文引出新话题 | 真人感 | 当前话题、关系、角色动机与真实材料；允许保持沉默 |
| “明早七点叫我”“每周提醒我交作业” | 主动消息 2.0 | 用户明确设置或委托的时间、周期与事项 |
| 编辑、取消、改期、查询明确排程 | 主动消息 2.0 | 已有任务及其授权 |
| 普通聊天生成、锁屏后的云端生成、推送与补收 | 共用执行与传输能力 | 发起方的独立授权；传输本身不产生聊天动机 |
| 人设、世界书、记忆、情绪、角色日程 | 现有共用上下文能力 | 为真实对话提供依据，不单独授权发消息 |
| 一起听邀请、切歌与其他显式互动 | 原有业务模块 | 对应互动自身的权限，不能被真人感或排程开关误拦 |

“主动”这个词不能用于判断归属。角色因为想聊而联系属于真人感；因为用户委托的明确时间到了而提醒，属于主动消息 2.0。共同使用 Worker 不代表它们属于同一个功能。

真人感关闭后的最终要求：不再以真人感的名义发起回复、找话题、补发或派生 API 请求。正在生成的相关请求需要停止，迟到结果不得重新激活。历史“普通自动回复”不得作为私聊的旁路继续运行；群聊输入偏好需单独处理，不能因此被误删。已向模型发出的请求无法追溯撤销已发生的费用。

## 当前代码现状（移植前整理阶段）

| 部分 | 当前实现 | 后续工作 |
|---|---|---|
| 用户发言后的自动回复 | `useChatAutoReply` → 既有 `useChatAI`；真人感与普通自动回复仍用 OR 授权 | 合并私聊授权与关闭链路；不能仅改显示文案 |
| 对话注意力、输入结束判断 | `realPersonReplyRhythm` 中的注意力判断 + `realPersonReplyReadiness` | 保留有效实现，按参考 APK 适配同一轮消息管理 |
| 话题跟踪 | 既有 M3 与 `realPersonReplyTurn` | 明确各层职责，避免再叠第二套话题系统 |
| 自然主动联系 | `amsgAutonomyWake` / `amsgAutonomyBootstrap`，仍由旧 2.0 配置和云端排程执行 | 业务授权与动机归回真人感；先完成旧任务停用与新旧代次隔离，再启用新机制 |
| 明确排程 | `amsg2ToolBridge` / `activeMsgClient` / `worker/amsg` | 保留排程能力；将自然找话题与明确委托区分，不能直接按“角色创建”批量删除 |
| 云端聊天、情绪回程、后台记忆整理 | 共用了 amsg Worker、收件箱与凭据 | 共用基础设施继续保留，不能因功能名字含 amsg 就误删 |

**本轮没有完成真人感自动行为的独立迁移，也没有把旧 OR 授权伪装成已经修复。** 不在新机制未接通前让“仅开启真人感、关闭 2.0”的用户突然获得新的付费后台主动行为。

## 本轮实际清理

1. 聊天页不再重复维护 OSProvider 已统一维护的自主联系任务。系统层继续负责启动、返回前台、真人感开关、日程改变和取消授权后的恢复。
2. 将手动任务占用名额、上限与时区变化纳入系统层的刷新输入。自主联系任务自身的保存与错误信息变化不重新触发维护，避免写回后循环对账。
3. 移除没有接入实际发送链路的旧随机等待计算器及其单独测试；移除仍能编辑但不生效的旧节奏设置面板、回调与 hook 参数。
4. 保留实际使用的连续对话注意力、忙碌/睡眠门禁、输入合并与真实发送判定。原角色资料中的旧秒数仅为备份兼容保留，不作为新的开启授权。
5. 本轮不新增提示词，不添加第二套自动回复或后台调度引擎，不改 2.0 Worker 协议，不清除用户已有排程、聊天或记忆。

## 后续适配的依赖顺序

1. 统一私聊许可来源，明确手动触发与自动接话的来源；停止、重试、工具续轮与结果落库都遵守该来源。不要依靠散落在界面的布尔判断。
2. 关闭时先撤销任务授权，再取消相关本地/云端生成与待办。复用已有停止机制，不能只清一个定时器或一条 localStorage 记录。使用新的授权代次阻止关闭前的异步回调在重开后复活。
3. 以真实消息 ID、同一段连续表达和生成身份管理回复；导入、失败发送、音乐卡片和旧自动消息不能被当作新的用户开口。切换角色、返回页面与多窗口不得重复回答。
4. 适配自然表达和可选的后续交流。参考 APK 的回复组织按需要使用，不把每轮聊天强制套成一套结构，也不靠额外的轮询 LLM 判断“该不该找话题”。
5. 迁移自然主动联系：区分 `autowake:` 任务、明确委托、角色自排任务和后台作业。旧任务必须先停止并核对；源字段不足时不能猜归属或整批清空。
6. 最后再整理提示词：人设与世界书保留；背景材料、当前状态、待回答消息和本轮表达各有职责。通过真实场景对照检查效果，不能把提示词数量或测试数量当作自然度证据。

验收至少覆盖：开启后单条/连续消息自然接话；输入中不抢话；关闭前待办、生成中关闭、重开后旧回调、换角色与多窗口；明确提醒继续工作；一起听、群聊、记忆和日程不受误伤。最终交付必须核实指定测试站 `preview-source.json` 的源码提交。

本轮验证：15 个相关测试文件共 342 项通过，覆盖现有自然接话、云端自主联系、明确排程、额度、即时对话与学习室提醒；清理后的最后补测 60 项通过。生产构建通过。全库 TypeScript 仍有既有错误，本轮修改文件没有诊断。此结果验证清理没有改变既有链路，不代表后续真人感独立移植已经验收。

关联 CI 收尾：自主联系任务的归属判断接受远端没有 `clientTaskId` 的投影，保持原有 `typeof` 判断；版本探测测试补齐发布通道字段。修正原有类型约束，不改变触发规则。

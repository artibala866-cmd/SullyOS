# 阶段 4：云端手机 NPC 待回复的有限自主延续

本阶段仅使用现有主动消息 2.0 Worker 的 `autowake` 每日自主联系机会。**不是**新增一套后台 AI 任务引擎，也不会偷偷开关、替用户创建额外付费的 NPC 轮询。

## 什么情况下会做

- 角色 **主动消息 2.0** 已明确启用，而且其 Worker 版本匹配、云端定时任务和推送可用。
- 用户另外显式开启 `chatPiggybackEnabled`（角色手机里的“私聊同轮生成”）。默认 `chatPiggybackEnabled=false`，**单开真人感/主动消息不授予手机 NPC 云端回话权限**。该选项与独立收费的 `backgroundApiEnabled` 及前台自主生活总开关彼此独立，和原来私聊同轮生成的开关含义保持一致。
- 手机中存在真实保存、时间戳有效、仍未回复、且距今不超过 72 小时的**虚构 NPC** 微信消息。没有保存的联系人/消息不是理由；已链接另一真实 Char 的联系人不可被 NPC 模拟。
- Worker 自动联系到点时，先确认这一则待回复消息尚未消耗。只有成功在云端保留一次性去重标记的机会，才向**原来这次**主动消息的同一模型提示里附上独立的手机回复说明（不新增 API 请求）。

## 数据流与不可越过的闸

1. `amsgCloudPhoneSelection` 从设备手机现有通讯录/微信找符合条件的待回复线程，仅在明确 opt-in 时随下一次 `fire_pack` 带**单条联系人和最近五条已保存手机聊天摘要**上云。原有聊天、手写联系人、记忆与 phoneState 不搬家、不覆盖。
2. 手机权限、联系人、微信变动时 `OSContext` 打脏原有 AMSG 云端快照，避免旧授权一直留在 Worker。
3. Worker 只在**自动联系**（不是手动提醒或即时聊天）任务，使用既有 `cloud_phone_last_reply_attempt` 作为服务端去重。云端即使没找到合适回复，也不重新买一次 API 来补；已经预留过的消息不会反复扣费。
4. 模型可自由选择不回 NPC。回复格式为 `[[CLOUD_PHONE_REPLY:{"messages":["..."]}]]`，严格不超过两段、每段不超过 160 字。Worker 无条件从给用户看的回复里移除内部标记，**手机 NPC 内容绝不作为用户私聊发送**。
5. 只有确实生成出合格 NPC 回复，Worker 才通过现有 `ctx.emitResult` 送 `cloud-phone-reply-v1` 到服务端收件箱，`notification.show=false`。如模型先执行工具，前一轮已生成的有效手机回复会保留到本次调用的终结轮再提交，避免工具流程意外吞掉回复。即使手机/浏览器关闭，结果可等下次上线补收；不会额外弹通知。
6. 设备收到后再次核查角色是否存在、2.0/手机权限是否仍开启、权限与清除版本是否仍匹配、NPC 联系人仍是虚构联系人、原微信最后一句没变、用户没有先回。任何条件失效就丢弃旧结果，**不复活删除的数据**。
7. 仅在确认实际追加到原微信线程后，记录来源为 phone 的 NPC-chat 生活事件；推送或收件箱重放使用稳定 `cloudSourceId` 防重复，并走现有生活事件同步管线。用户删掉原微信线程时，对应派生事件也会被清掉。

## 不宣称已经完成的范围

- 云端无法运行浏览器的完整 localStorage/IndexedDB 手机引擎。**本次仅做已有虚构 NPC 待回复消息的云端延续**，没有实现应用杀死后随时生成新 NPC、自己发朋友圈/评论、真正的真人双向私聊，或完整的 24 小时角色独立生活。
- Worker 使用用户自己部署的新版本 bundle（`AMSG_BUNDLE_VERSION=2026-10-30.3`）。只更新开发预览网页**不会自动更新用户的 Cloudflare Worker 实例**。旧版不能执行本轮新增的 NPC 云端回程。
- 同一次自主联系的 LLM 仍会消耗主对话 API；`[[SILENT]]` 只是“不联系用户”，不等于这一轮没有调用模型。
- 应用完全关闭时、未在服务端提前存在的手机事件无法由 Worker 猜出。角色的计划不等于已发生事实；云端不得补造线下经历。
- 没有真实 Worker 账号及 Android 设备的端到端连通性测试，源代码回归成功只能证明逻辑与编译，不代表用户已经成功收到云端消息。

`.github/workflows/character-life-stage4-cloud.yml` 执行主动消息/角色手机回归、源文件 TypeScript 检查，以及 `pnpm build:workers` 真正打包。仅在 `remove-checkphone-vrworld-lifesim` 开发，独立预览站 `https://artibala866-cmd.github.io/SullyOS-Dev-Preview/`；不更改 master、正式部署配置或用户旧记录。

## 2026-10-30 后续安全补丁

- 云端与角色手机本地私聊**共用“同轮生成”开关语义**：独立收费的手机后台请求关闭时，已经明确同意的云端自主联系同次附带不被误拦；没有显式授权时绝不附带。
- 多轮模型工具调用时，先前有效的 NPC sidecar 会保存到终结轮后再经现有结果收件箱发送，不会被下一轮文字清空；一个 fire 仅发送一次。
- 选择待回复对象时，排除链接其他真实 Char 的联系人，**不会因为他们的旧消息排在前面就饿死所有虚构 NPC**。没有与真正 NPC 对应的已保存待回消息就不发。
- 手机接收端在同一次同步存储变更中再次检查线程、消息条数、最后一句和时间戳，杜绝“用户删除旧聊后结果刚好迟到”而建回旧聊。云端稳定 ID 防重优先于普通短句文字防重：两句确实分开发出的“嗯”不能被误判重复；重放相同 ID 则不能存两遍。
- Worker 若没有可靠的 `emitResult` 回程，不能消耗那条 NPC 联系机会；本轮后端兼容性变化通过 `2026-10-30.3` 版本提示用户更新，绝不擅自部署用户的 Worker。
- 角色手机设置页显示“是否授权”和“本地是否有符合条件的待回 NPC”；它不把本地候选当成云端成功运行，也不承诺一定回复。

## 2026-10-30 联系人删除和多会话安全补丁（Worker 2026-10-30.3）

- `cloudPhoneOpportunity` 与 `cloud-phone-reply-v1` 现在携带虚构 NPC 联系人的 `createdAt` 和“清空手机联系人”的独立清除版本。用户清空通讯录、重建同 ID 联系人或删除后重加时，旧 Worker 结果**不得被写入新联系人**；旧协议缺失这些身份字段也不能绕过校验。
- 同一联系人有多个已保存微信会话（旧备份、导入）时，云端回复按其原始 `threadId` 精确找到会话，而不是盲目修改该联系人列表里的第一项。原会话已变成群聊/服务号后，不得作为虚构 NPC 私聊继续写入。
- 此次对“Worker 发起实际 AMSG 自主机会 → 云端结果收件箱”的测试做协议更新：`[[SILENT]]` 可同时产生独立的跳过诊断结果；验收只统计 `cloud-phone-reply-v1` 类型的 NPC 结果，**不能把合法诊断当成重复发 NPC**。
- 这仍不是完整 24 小时 NPC 手机系统，也不会更新用户自己的 Worker；必须让用户自行部署与当前网页同版的 `2026-10-30.3` Worker，真实 API/Cron/Push 的端到端送达还需设备测试。

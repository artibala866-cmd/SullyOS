# user 身份 · 独立存档（第一阶段）

入口：个人档案 → 我的档案 → user 身份 · 独立存档。沿用现有卡片、表单和 Modal。

- 第一个身份直接使用原数据库及原 localStorage 键，不搬迁、不清空旧记录。
- 新身份使用独立主数据库、协同数据库及主动消息辅助库；localStorage / sessionStorage 默认隔离未知键。
- 每个页面生命周期固定绑定一个身份。切换先写完目标存档，再更新身份索引并整页重载；旧异步工作只能写回旧库。其他标签页收到身份切换事件后重载。
- 角色、世界书、角色分组、表情包、主题、剧情预设等基础资料在切换时同步；角色字段用显式白名单选取。角色原始定义和外观共用，新增未知字段默认归本身份，不自动继承。
- 新身份不继承聊天、宫殿、记忆水位、日程、剧情条目、生成的生活记录、关系/拉黑、情绪、待回复或自动互动授权。
- 3D 小屋只继承房间外观，不继承活动、记录、配对、宠物进度或自动行动授权。
- 只复制基础资料引用的 Blob；不复制聊天图片历史。目标身份自己的记录、头像和资料继续保留。
- 远程宫殿的 char_id 和 memory_id 在新身份使用 `user:<identity-id>:` 命名空间，原身份保持旧远程 id，避免相同角色串远程记忆。
- 无身份标记的旧 Service Worker 推送仅由原身份运行时接收；新身份不启动该旧后台入口，也不继承原云端账号设置。
- 目标库写入失败、配额不足、索引无效、其他标签页抢先切换时不激活目标。未列入索引的新建失败数据库可安全清除。

## 本阶段边界与下一阶段

现有备份/恢复与清理针对当前使用的身份；不是全部身份打包。各身份仍需分别备份。共用角色/世界书的编辑、导入或删除会在下一次切换传播，请不要把共用角色删除当作单条故事清档。

下一阶段优先实现全身份备份/恢复、身份索引恢复与身份重命名；在备份链路验证前不提供删除身份或一键清档入口。

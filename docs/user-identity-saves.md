# user 身份 · 独立存档（第二阶段）

入口：个人档案 → 我的档案 → 头像/名字资料卡底部的「身份存档」。不再在顶部创建独立大卡；沿用现有表单和 Modal。

- 第一个身份直接使用原数据库及原 localStorage 键，不搬迁、不清空旧记录。
- 新身份使用独立主数据库、协同数据库及主动消息辅助库；localStorage / sessionStorage 默认隔离未知键。
- 每个页面生命周期固定绑定一个身份。切换先写完目标存档，再更新身份索引并整页重载；旧异步工作只能写回旧库。其他标签页收到身份切换事件后重载。
- 角色、世界书、角色分组、表情包、主题、剧情预设等基础资料在切换时同步；角色字段用显式白名单选取。角色原始定义和外观共用，新增未知字段默认归本身份，不自动继承。
- 新身份不继承聊天、宫殿、记忆水位、日程、剧情条目、生成的生活记录、关系/拉黑、情绪、待回复或自动互动授权。
- 3D 小屋只继承房间外观，不继承活动、记录、配对、宠物进度或自动行动授权。
- 只复制基础资料引用的 Blob；不复制聊天图片历史。目标身份自己的记录、头像和资料继续保留。
- 远程宫殿的 char_id 和 memory_id 在新身份使用 `user:<identity-id>:` 命名空间，原身份保持旧远程 id，避免相同角色串远程记忆。
- 无身份标记的旧 Service Worker 推送仅由原身份运行时接收；新身份不启动该旧后台入口，也不继承原云端账号设置。
- 目标库写入失败、配额不足、索引无效、其他标签页抢先切换时不激活目标。未列入索引的新建失败数据库可安全清除。

## 全部身份备份与恢复

设置 → 备份与恢复 → 备份范围可选择「当前身份 / 全部身份」，复用现有导出按钮与导入文件入口。原来的纯文字/媒体分步备份仍只针对当前身份。

- 全部身份 ZIP 保存每个主库/协同库的独立快照、记录主键与索引、localStorage、本地媒体、向量二进制和视频模型。二进制按 SHA-256 去重，JSON 分片写出，不把所有记录合成一个巨型字符串。
- 导入先在全新数据库中恢复为独立副本，再发布身份列表；不会覆盖原有身份。损坏文件、数量不符、配额不足或身份列表发生变化时拒绝发布并清理准备数据。
- 恢复副本保留聊天、宫殿、剧情等互动数据；只向当前基础库补充缺失角色/世界书/装扮，已有同 ID 基础资料保持当前版本。私人聊天图片不会进入当前身份的素材库。
- 当前已有外观和 API 设置保留；共用设置缺失时才补充备份中的值。恢复副本不自动连接原来的远程宫殿、实时在线账户、云备份目标或旧 Worker 任务；这些需用户重新配置。资源下载缓存不入包，可重新下载。
- 最后写入身份索引失败时，只回滚本次补入且未被其他页面编辑的基础条目；不删除已有游戏数据。无引用的二进制可能保留，后续资源优化可回收。
- 备份/恢复期间阻止本页切换、新建与重命名；其他标签页修改身份索引时中止本次操作。各库内部使用一致的只读事务快照，不承诺多个独立数据库之间的分布式事务快照。

身份栏支持重命名列表标签，不修改人物资料、存档编号、聊天和进度。共用角色/世界书的编辑或删除仍会在切换时同步；删除角色不等于删除某条故事线。

全部身份恢复会增加本地空间占用。现有清理入口仍针对当前身份；尚未提供删除身份或全身份一键格式化。下一阶段需完善身份索引的本地灾备恢复，再设计身份删除与对应恢复流程。

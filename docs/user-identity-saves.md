# user 身份 · 独立存档（第二阶段）

入口：个人档案 → 我的档案 →「你的名字」输入框右侧的小箭头。选择身份即切换；原名字输入框、头像上传和下方「关于我 / 设定」直接编辑当前身份。仅显示小加号与垃圾桶，不另建身份栏或切换/重命名按钮。

- 第一个身份直接使用原数据库及原 localStorage 键，不搬迁、不清空旧记录。
- 新身份使用独立主数据库、协同数据库及主动消息辅助库；localStorage / sessionStorage 默认隔离未知键。
- 每个页面生命周期固定绑定一个身份。切换先写完目标存档，再更新身份索引并整页重载；旧异步工作只能写回旧库。其他标签页收到身份切换事件后重载。发起切换的页面通过目标身份绑定的一次性会话标记直接返回档案，不重新进入开屏/锁屏；正常冷启动保持原样。
- 角色、世界书、角色分组、表情包、主题、剧情预设等基础资料在切换时同步；角色字段用显式白名单选取。角色原始定义和外观共用，新增未知字段默认归本身份，不自动继承。
- 新身份不继承聊天、宫殿、记忆水位、日程、剧情条目、生成的生活记录、关系/拉黑、情绪、待回复或自动互动授权。
- 人物身份外貌不属于界面外观：新身份使用中性默认头像，名字为可编辑的新身份名称，设定为空；不继承整体头像、分角色用户头像、生图外貌/锁脸参考图、用户衣橱、用户捏人形象或彼方状态。切回已有身份保留该身份自己存下的全部资料，不覆盖为新档默认值。
- 3D 小屋只继承房间外观，不继承活动、记录、配对、宠物进度或自动行动授权。
- 只复制基础资料引用的 Blob；不复制聊天图片历史。目标身份自己的记录、头像和资料继续保留。
- 远程宫殿的 char_id 和 memory_id 在新身份使用 `user:<identity-id>:` 命名空间，原身份保持旧远程 id，避免相同角色串远程记忆。
- 无身份标记的旧 Service Worker 推送仅由原身份运行时接收；新身份不启动该旧后台入口，也不继承原云端账号设置。
- 目标库写入失败、配额不足、索引无效、其他标签页抢先切换时不激活目标。未列入索引的新建失败数据库可安全清除。

## 全部身份备份与恢复

设置 → 备份与恢复 → 备份范围可选择「当前身份 / 全部身份」，复用现有导出按钮与导入文件入口。原来的纯文字/媒体分步备份仍只针对当前身份。

- 全部身份 ZIP 保存每个主库/协同库的独立快照、记录主键与索引、localStorage、本地媒体、向量二进制和视频模型。二进制按 SHA-256 去重，JSON 分片写出，不把所有记录合成一个巨型字符串。
- 导入先在全新数据库中恢复为独立副本，再发布身份列表；不会覆盖原有身份。损坏文件、数量不符、配额不足或身份列表发生变化时拒绝发布并清理准备数据。
- 恢复副本保留聊天、宫殿、剧情等互动数据；只向当前基础库补充缺失角色/世界书/装扮，已有同 ID 基础资料保持当前版本。私人聊天图片不会进入当前身份的素材库。
- 当前已有外观和 API 设置保留；共用设置缺失时才补充备份中的值。恢复副本不自动连接原来的远程宫殿、实时在线账户、云备份目标或旧 Worker 任务；这些需用户重新配置。资源下载缓存不入包，可重新下载。
- 最后写入身份索引失败时，只回滚本次补入且未被其他页面编辑的基础条目；不删除已有游戏数据。无引用的二进制可能保留，后续资源优化可回收。
- 备份/恢复期间阻止本页切换、新建与重命名；其他标签页修改身份索引时中止本次操作。各库内部使用一致的只读事务快照，不承诺多个独立数据库之间的分布式事务快照。

名字输入同时更新人物资料和切换列表中的名称，头像与下方身份设定各自随当前身份保存。新建直接创建空白互动存档并进入，可立即编辑；垃圾桶移除当前身份并转入另一个身份，底层数据暂保留，防止误删或旧异步写入造成数据破坏。最后一个身份禁止删除。共用角色/世界书的编辑或删除仍会在切换时同步；删除角色不等于删除某条故事线。

全部身份恢复会增加本地空间占用。现有清理入口仍针对当前身份；删除入口只移除列表身份，不永久清理底层数据库；尚未提供全身份一键格式化。下一阶段需完善身份索引的本地灾备恢复，再设计身份删除与对应恢复流程。

## 2026-11-07 空白新档边界复核

参考用户提供的 MarshmallowMachineNext-v0.1.0-next.61 APK 的内置 JS（仅读取机制，不移植模块）：

| APK 入口/机制 | 实际行为 | 糯米机本次选择 |
| --- | --- | --- |
| `core/user-slot.js:createUserSlot` → `models/user.js:createUser` | 新 ID/世界/档位容器；头像和 persona 等使用空白默认值 | 「＋」仅接受新名称，构造全新 user_profile，不接收源 profile |
| `createUserSlotFromIdentity` | 复制身份资料开新世界线，不复制聊天和记忆 | 用户没有要求复制身份，不接入 |
| `duplicateUserSlot` | 连同同档身份、关系网络、熟人账、手机联系人复制 | 与空白新存档需求不同，不接入 |
| `applyCurrentUserId` | 更新指针后发事件，要求清除页面缓存 | 保留糯米机整页重载和绑定数据库机制，避免旧状态残留 |
| userId / worldId 所属记录 | 聊天、记忆、社交、番外等按归属隔离 | 保留原库，使用每身份独立库及默认隔离存储键；不搬参考 APK 的业务模块 |

角色卡、世界书与界面装扮仍为基础资源，不把 APK 中的世界书归属规则照搬到糯米机。人物本人的脸、形象与锁脸引用则全部属于身份数据。

修复之前将人物头像等误当成“外观”复制的问题。新增回归在所有实际私有 object store 中写入旧档哨兵，逐库验证新档为空且旧档未改变；另设只有身份引用的 Blob，确认这些照片不复制进新档。独立验证空白资料、实际编辑后的 A/B/A/B 往返，原身份及已有身份均不被重置。

不自动清空旧版本已经创建并保存的身份资料：无法区分用户主动选用同一头像与旧代码的继承值，不能据此擦掉已保存的脸或设定。

补齐三处原来没有等 profile 事务完成就显示成功/关闭的问题：用户手办、分角色头像、锁脸上传。保存操作期间不允许发起切档，失败会报告并保留编辑入口；分角色头像按最新 profile 合并，避免上传等待期间覆盖另一角色的头像。

独立衣橱入口 `chibi-wardrobe.html` 及开发实验入口现在也先安装身份存储隔离：避免独立页面的服装/外貌草稿直接读取原身份的裸 localStorage。跨页切换身份后随宿主身份变更重新载入；原身份草稿仍保留。浏览器回归真实打开独立衣橱页面，验证 A 的草稿标记在 B 中不会出现，再回到档案继续检查。


## 桌面图片随身份切换的修复

外观复制同时扫描共用设置（包含 os_theme 的桌面照片和自定义 CSS）引用的图片，不再只扫描 assets 表。桌面装饰及其编辑预览统一解析 Blob 令牌。旧版本已经缺图的身份会在加载外观前，按共用外观明确引用的图片 ID，从仍保留的身份数据库补齐；已软删除身份的底层库也可提供这些共用图片。只补缺失文件，不改头像、聊天图片、记录、桌面排版或配色。原文件已不在任何本地存档中时无法凭地址重造。

回归包含主题独有引用、CSS 引用、私密图片不复制、软删除原身份的修复，以及真实 Launcher 的胶片照片、背景照片、拍立得和装饰图片在新档与人为删去图片后的重载恢复。

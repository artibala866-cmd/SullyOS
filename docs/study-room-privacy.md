# 学习室 · 私聊授权和到点提醒隔离

实现位于 `utils/sullyWorkspace.ts`、`utils/workspacePrivateChat.ts`、
`apps/WorkspacePanel.tsx`、`utils/studyRoomReminders.ts` 和 `hooks/useChatAI.ts`。

## 授权规则

- `sully_workspace_v1` 仍保存在本机 IndexedDB assets，与旧自习室课程和番茄钟数据隔离；完整备份沿用原 assets 导出。
- `privateChatPermissions[charId]` 有 `study` 和 `commissions` 两个明确的布尔值，缺失、旧备份或非 true 值都视为 **关闭**。不同 Char 之间不继承权限。
- 仅 ChatApp 普通私聊在每一轮将要发送时读取该角色授权；同一轮的本地生成/即时对话共用同一份结果。不修改原先的 `ChatPrompts`、角色卡、世界书或 AMSG fire_pack。未授权时返回空块，连标题都不提供。
- 开启学习共享只包含课程名称、星期、上课时间、作业名称、截止时间和完成状态；画稿共享仅包含匿名序号、标准阶段、状态、日期和剩余时间；**不包含稿名**（稿名里也可能写客户姓名或订单号）。老师、地址、客户、约定价格、详细需求、委托备注、课程笔记、作业笔记及 PDF 原文始终不共享。列表有数量与字符长度上限。
- 用户主动点击学习室里的「问 Char」「提问」属于**另一次明确发给 AI 的请求**，不是正常私聊授权开关的后台读取。编辑内容不会由模型自动覆盖。
- 关闭授权立即阻断以后的 ChatApp 请求读取；已经向模型发送过的内容、已生成的回复和历史记忆**不会因此自动清除**。已经在发送中的请求也无法撤回。

## 关联提醒

- AMSG 2.0 固定提醒仍须逐项手工确认，默认不建立；不调用 AI 生成到点消息。
- 关闭某角色的一个共享分类时**先落库撤销共享**，再尝试取消该角色对应分类的固定提醒。不会触碰其他角色或其他分类。
- 远端取消失败、创建结果不明或者本地记录没有远端 UUID 时不能标成「已取消」：保留记录和任务身份，UI 显示数量、错误、AMSG 核查提示。绝不盲重试创建，以免幽灵任务或重复推送。
- 重新开启私聊共享**不会**自动恢复已取消的提醒；提醒和共享是两次分别的授权。

## Char 排单建议（用户发起、逐项确认）

- 画师排单的「让 Char 帮我排一下」仅打开学习室原有 Char 对话框，须用户再点发送；不新增 API 请求、不自动付费、不将背景同步到普通私聊。
- 本轮主动请求仅包含进行中的委托 ID、稿名、当前阶段、合同截止日、计划日、剩余工时/缓冲/优先级，以及课程时段、作业预估工时和每日可用时间；不包含客户姓名、价格、详细需求、私人备注、收款情况或 PDF 原文。稿名由用户主动点击后发送，可能由用户自行填写敏感内容。
- AI 响应必须是 JSON changes 数组；只接受同一请求已知 ID 的计划日期、剩余分钟、优先级及理由。发现客户/价格/交期/完成状态等越权字段、重复 ID、越界日期/工时、非 JSON 时，**整份方案拒绝**，不会静默应用。
- 接受解析结果只生成预览，默认未勾选。逐项选择后对比风险，用户再次确认才在 `mutateWorkspace` 串行事务内更新白名单字段。应用前严格比对委托与课程/作业计划版本，拒绝过时的方案；不自动取消或调整 AMSG 提醒，也不自动承诺客户交期。
- 风险计算沿用 `calculatePlanRisks`：关注交稿日期前可用时间与累计欠工。计划日期本身未实现硬性日程容量锁定，界面明确说明。
- 测试入口：`utils/commissionPlanProposals.test.ts`，纳入现有学习室 CI 定向类型检查与 Vitest 门禁。

## 学习室课程表与独立 PDF 自习室关联

- 原有 `StudyCourse` 继续独立保存于 IndexedDB `courses`。学习室 `TimetableClass.studyCourseId` **只存引用 ID**，不拷贝/移动旧 PDF 文本、章节讲解、测验、进度或其它课件。
- 课程表页面用 `DB.getAllCourses()` 加载旧课程选项并展示实时课程进度与已完成章节。选择关联时再次读取旧列表，不允许新增指向已不存在课程的 ID；解除关联只删本地引用。
- 点击「打开关联自习室课程」进入**旧自习室书架并高亮对应封面**。用户再次点击封面才进入原有课堂，避免单纯浏览关联就启动有成本的 AI 教学。自习室原入口不变。
- 如果旧课程已被单独删除或旧备份未包含该课，课程表显示“旧关联失效”，保留 ID，不自动删除学习室课程与资料，可手动换绑或解绑。课程表和旧课程不自动双向改名/同步进度。
- 课程表删除仅删除当前课程表行；原有自习室书库不变，原作业/笔记仍保留（成为“未归属资料”）；未归属区域允许重新归类作业和笔记，原文与完成状态不变，孤立作业也可继续专注。旧备份中已有的孤立内容直接展示，不做有损迁移。
- 课程的作业条目仍提供原有「为作业开始专注」，选定关联课程后还可以直接去原有自习室复习；不会自动勾选完成作业、改写笔记或自动发消息给 Char。
- 测试 `utils/studyCourseLinks.test.ts`、`utils/studyCourseLinks.wiring.test.ts` 检查链接、解除关联、孤立记录恢复、旧课程只读和 UI 跳转接线。

## 既有功能深度审计与修补（2026-10-29）

- **修复整份 UI 快照回写**：先前 `WorkspacePanel` 的 `useEffect` 会在远端提醒／授权状态更新后，把旧的课程、委托、作业数据整体重新写入。现在 `change` 捕获每次 UI 改动的 before/after，通过 `mergeWorkspaceLocalEdit` 针对单条记录的具体字段在最新数据库版本上合并；并发同字段修改明确报错，绝不悄悄覆盖新值。异步识图批量导入和新增笔记在调用前固定新 ID。并不承诺跨独立浏览器标签页的全局事务锁。
- **底层创建提醒二次校验**：只允许真实存在、未完成的作业与 active 委托创建提醒；创建前和序列化入库时分别检查。若远端创建期间事项完成、删除或授权撤回，拿到远端 UUID 后尝试补偿取消；远端取消失败保留 UUID 和 `cancel_failed`，无法确认创建结果时保留 `needs_review`，需人工在 AMSG 核对。已失去父课程的作业也可在「未归属资料」找到提醒记录并手动取消。
- **隔离各 Char 的学习室监督聊天历史**：新增消息带 `charId`，新请求只载入该 Char 自己的历史。旧版本无角色 ID 的记录在本机单列查看，不会再传入任意 Char 的提示上下文。切换角色或切换讨论主题期间返回的迟到回复不再应用为当前角色的排单预览。
- **排单跨日失效**：用户生成建议后若跨到新本地日期，必须重新生成；防止第二天套用昨天计算的计划。课程时间冲突使用重叠区间合并，避免两门同时上课重复扣时。自愿「问 Char」单稿件摘要不再默认带上私人委托备注。
- 回归用例涵盖字段级冲突合并、角色隔离、远端创建／撤销竞争、跨日建议、重叠课程扣时、孤立作业可核查提醒。仍须在真实 Android、实际跨标签页并发、真实 AMSG Worker 上做人工验收，自动化模拟不能替代设备环境。

## 第二轮审计补齐：并发事务、损坏备份、云端核查与日容量

- **跨标签页原子事务：** `utils/db.ts` 新增 `updateAssetRaw`，整个同步变更回调在一个 IndexedDB `assets` readwrite 事务的 get.onsuccess 中计算并 put；直到 transaction.oncomplete 才确认成功。不同标签页使用同一个 IndexedDB store 事务队列，和原先「读完再另外开事务写」不同。学习室 `mutateWorkspace` 与 `writeWorkspace` 使用该原子接口，页面级 `workspaceEditMerge` 仍用于检测同字段冲突。不同设备/备份导入后再覆盖属于另一个同步问题，未自动处理。
- **损坏备份保护：** `normalizeWorkspace` 仅读出可识别 ID 的正常记录，对部分缺失字段做显示默认值；`workspaceIntegrityWarnings` 检查数据集合、无效/重复 ID、缺少关键字符串。发现异常时原始 IndexedDB 数据不清理，原子写入拒绝覆盖；面板显示风险及建议恢复健康备份。此机制是 **只读安全保护** 而非自动修复所有损坏资料，未处理损坏源仍不可编辑。
- **AMSG 主动核查：** 用户逐项点击「读取 AMSG 云端状态（不修改）」才调用旧有 `listRemoteTasksForChar`，必须以同 Char 的 UUID/客户端任务 ID 严格匹配，不发起新任务、不自动删除本地链接。没有可靠任务号时显示「无法识别」，列表未找到也不自动认定云端不存在。真实网络认证/Worker/Android 通知需人工验收；不得据列表结果自行复创建。
- **按天容量估算：** `dailyCapacityForecast` 单独显示课程占用、作业分钟、逾期未做作业、当日可用/超额分钟。没有有效截止时间的作业显式报未安排，不虚构日期；共享 `calculatePlanRisks` 风险口径，跨 DST 使用日期键差而非 23/25 小时推算天数。仅为每日预算估算，不是精确小时级自动排程。
- 定向测试 `workspaceIntegrity.test.ts`、`dailyCapacityForecast.test.ts`、`workspaceAtomic.wiring.test.ts`，连同已有 AMSG 及权限测试一起纳入独立 CI。

## 人工恢复损坏备份

- 若工作空间来源损坏，界面显示详细异常并阻止常规写入。用户选择「确认后备份原件并恢复可识别资料」，须再次输入指定确认词。
- `DB.recoverAssetRawWithSnapshot` 在同一个 `assets` readwrite 事务里，先检查新快照 ID 未被占用，**同时**写入完整受损原件到 `sully_workspace_recovery_<uuid>`，再用经过校验和补全的条目替换主 `sully_workspace_v1`。事务任何阶段失败均不能完成主空间替换，不能覆盖旧快照；完整备份导出能包含该原件快照。
- 无法识别/重复 ID 条目不进入新的工作空间显示列表，但保留在原始快照中供人工恢复；可能丢失的 AMSG 提醒标识不会自动删除云端任务，必须人工核对。非交互式代码无法调用此恢复操作。
- 测试除了安全只读和拒绝损坏写入，还包括人工确认缺失、原件快照完整性、可读资料迁移，以及恢复后正常读写。

## 学习室核心任务闭环：专注记录人工结算到委托与作业

- 原始工作流：课程表手工创建作业或画稿委托 → 在该事项点击「专注」→ 完成整轮番茄钟 → 在专注统计中核对来源、实际分钟 → 返回原画稿／作业，人工确认结算。不是额外的章节绑定系统。
- `sully_pomodoro_v1_records` 仍是原有本地专注记录，不挪动旧数据；每条有 `sessionId` 的**完整专注轮次**可参与结算。旧版无唯一轮次 ID 的记录仍显示在累计专注中，但不自动抵扣，避免重复扣工时。
- 新 `focusSettlements` 保存在同一份 `sully_workspace_v1`，每轮只登记一次已应用的唯一 ID、原事项 ID、类别、分钟和时间。结算通过 `mutateWorkspace` 原子事务重新校验事项存在、尚未完成／仍可执行、预计剩余分钟与用户确认前一致、选中轮次确属该事项且未结算。多标签页不能重复结算同一轮。
- 手工确认只减少委托 `remainingMinutes` 或作业 `minutes`，最小为零。**绝不自动设置完成或付款、修改交稿截止日期、设置云端提醒、触发 AI 调用或复制旧 PDF。** Char 排单建议的来源版本也会因为剩余分钟变化而失效，避免覆盖新核算结果。
- 作业现在可手工编辑预计剩余分钟；专注任务列表／统计可以返回原事项核对。孤立作业的专注记录亦可手动结算，但不会被自动重新归入课程。
- 结算历史与原有数据一样随本机工作空间备份；旧备份缺少 `focusSettlements` 默认为空。已损坏的结算账本被完整性检查拦截，避免重复使用未知记录。
- 测试 `utils/studyFocusProgress.test.ts` 和 `utils/studyFocusProgress.wiring.test.ts` 覆盖人工确认、旧记录、一次性结算、跨事项禁止串扣、编辑冲突、完成状态不变及页面入口。尚需真实浏览器人工确认用户流程的交互体验。

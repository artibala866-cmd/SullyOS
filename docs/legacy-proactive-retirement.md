# 主动消息 1.0 退役边界

独立的本地间隔主动聊天、旧 Push 加速器与 `[schedule_message]` 延迟文字发送已移除。2.0 的定时任务、即时对话、云端补收、普通自动回复、真人感生活节奏、日程与学习室提醒继续使用既有实现。

- 不再向模型提供本地排程标签，不再保存或投递本地延迟消息。旧历史与旧 Worker 返回的标签只清除，不执行；兼容的 directive 类型不代表保留发送能力。
- 删除旧加速器前端、隐藏设置、监听及独立部署目录。保留共用 Service Worker、VAPID 与 2.0 推送订阅；不注销或重新创建订阅。
- 启动、返回前台与导入前运行 `retireLegacyAiMessages`，读取旧队列全表，包含已删除角色的孤儿任务。原生端先取消可确认归属的系统通知，再删除对应旧队列行；失败保留标识供后续重试。旧无通知 ID 的行仅按角色名和正文匹配，无法确认时保留清理记录并报错，不猜测取消其他应用提醒。已显示的系统通知与其他设备需另行确认。
- `scheduled_messages` 本地表仅作兼容清理，不再有生产写入/派发入口，不升级数据库版本或删除整库。备份不再导出旧队列；旧备份的 `scheduledMessages` 输入忽略。角色 `proactiveConfig` 在本地迁移、保存、导入与导出时剥离；角色卡旧字段仍在剥离名单中。
- 导入前清理使用原角色名称，避免替换角色后丢掉旧通知的匹配依据。取消失败时阻止本次恢复继续覆盖，保留原有数据以便重试。
- 本次不访问用户实际部署的旧 Worker 或删除远端服务。前端不再向旧加速器注册或心跳。旧加速器只负责唤醒，不保存聊天或调用 LLM；2.0 云端任务不在本次清理范围内。已打开旧版本的窗口需刷新才能停用其旧代码。

验证：旧标签无数据库/通知写入；本地、云端打包与即时对话提示词都不再教旧排程；原生清理失败重试/未知归属保护；真实 IndexedDB 迁移、旧备份导入与导出；2.0、自动回复与备份回归及生产构建。

本次本地验证：专项 42 项通过；与 CI 相同的自动回复/AMSG 回归 281 项通过；扩展回归 598 项通过、9 项失败，使用修改前 `adee8be` 源码在相同离线环境中复现了完全相同的 9 项失败。生产构建通过。全库 TypeScript 检查仍存在既有错误（含统计字段与音乐钩子类型）；本次新增代码与修改行未产生新的诊断。未在用户实际 APK 上验收系统通知取消，也未访问用户 Worker。

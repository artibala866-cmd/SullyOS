# 真人感移植前：日程、查手机、学习室与主动消息 2.0 关联审计

审计日期：2026-11-02。当前源码基线 `0188c82`（包含前两轮清理）；原作者只读基线 `qegj567-cloud/SullyOS@e1c33c5b77fd1533208c2a26950b7b24b8bc13e1`；棉花糖参考为用户提供的 `MarshmallowMachineNext-v0.1.0-next.61.apk.1` 中 JavaScript。结论是静态调用检查与离线回归，不是 APK 真机效果或用户云端实例验收。未读取用户 Key、调用付费模型或更改个人开关。

## 原版基线与处理原则

原版 `utils/amsgFireSchedule.ts:buildAmsg2ChatScheduleBrief` 明确允许角色根据惦记、生活分享、承诺安排未来联系。因此原版 2.0 并非只有闹钟。它还包含即时聊天、后台任务及记忆整理。当前新增的 `amsgAutonomyWake` 每日联系机会不在这份原版基线中；原版也没有当前 `CharacterPhone.tsx` 这套新增手机的 NPC 云端搭车系统。

回归原版职责应该对新增绑定做增量拆分，不应整分支覆盖：那会覆盖已确认的手机、学习室、隐私、取消及迟到结果防护。历史 `apps/CheckPhone.tsx` 也不是当前手机的等价实现，不能借此恢复已退役功能。

## 调用关系与取舍

| 模块 | 当前真实关系 | 处理结论 |
|---|---|---|
| 日程生成 | `scheduleGenerator`、`dailyScheduleForegroundRecovery` 直接请求模型；依赖日程自身许可与配置，不以 2.0 或真人感为必需条件 | 保留独立日程；自动生成是单独付费许可，不可从真人感开启推导授权 |
| 日程读取 | `scheduleInjection`、`characterLifeScheduleContext` 为聊天、手机和云端任务提供计划/事实材料 | 保留只读上下文。计划不等于已发生事实；读取不应顺带触发生成 |
| 日程 → 新增每日联系机会 | `amsgAutonomyWake` 以作息规划每日联系，真人感和角色 2.0 开关共同授权 | 后续从 2.0 产品职责中拆出；先取消可识别旧任务、隔离迟到结果，再启用真人感新机制 |
| 手机独立后台活动 | `characterPhoneAutonomy` 与 OSContext 的机会处理使用手机总开关、后台 API 许可和预算，不要求 2.0 开启 | 保留手机数据和独立许可；未来纳入清晰的自动活动暂停规则，不能粗暴替换成一个真人感布尔值 |
| 手机 NPC 云端搭车 | `amsgCloudPhoneSelection` / `activeMsgClient` → Worker → `amsgCloudPhoneResultApply`；需要 2.0 和搭车许可，借每日联系请求生成 NPC 内容 | 属于新增绑定，建议退出 2.0 联系排程。保留旧结果的撤权、删除与版本检查，迁移前不可只删客户端入口 |
| 手机生成互斥 | `amsgChatGenerationLease` 避免同一角色生成冲突 | 保留。名字有 amsg 不代表它是 2.0 的业务许可 |
| 学习室固定提醒 | `studyRoomReminders` 通过 ActiveMsgClient 排程/取消，依赖角色 2.0、凭据及任务名额；固定文本提醒不需到点请求模型 | 保留合理关联，归 2.0 定时能力；完成、删除和撤回分享要取消提醒 |
| 学习室自动陪伴 | 实际入口在 `apps/ScheduleApp.tsx`，`allowAutoAI`、陪伴等级和暂停控制直接模型请求；并不由 2.0 执行 | 自然陪伴属于真人感适配范围；保留学习室自己的内容、许可和取消机制，不再另造一套普通私聊自动回复 |
| 学习室资料进入普通私聊 | `workspacePrivateChat` 根据按角色明确分享范围构建本轮上下文；`useChatAI` 读取 | 保留隐私边界。授权读取资料不等于授权主动发言，也不应整体塞进世界书或持久云端模板 |
| 云端即时聊天、记忆、情绪与结果补收 | 原版和当前共用 Worker、凭据和结果通道 | 保留。不能为了移走每日联系而连带删除公共执行和传输设施 |

当前手机关闭“独立后台 API”不等于关闭可选的“云端搭车”；搭车减少一次独立请求，但仍增加本轮 token。不能在 UI 或说明中把它称为完全不消耗 API。

## 棉花糖实际适配方式

参考 APK 不是靠一段“更像真人”的提示词实现，也不是把所有模块都挂到主动消息总开关：

- `character-autonomy-settings.js` 关闭真人感会取消对应回复/延迟/追话任务，并中止相关 headless 回复。需要连同在途请求和迟到回调一起撤权。
- `chat/marshmallow-presence.js` 由真实保存的用户消息建立回复批次；`chat/real-person-reply-timing.js` 区分输入结束与定时模式。导入消息和非真实发言不能触发第二次回复。
- `character-phone-proactive.js` 的输入结束模式，在没有明确授权硬离线且没有已登记系统自动回复时，自动忙碌状态和日程只影响内容，不能静默阻断待回复消息；手动忙碌/离线另有明确门禁。
- `character-phone-chat-scheduler.js` 排除包含 `user` 的聊天，手机 NPC 自动活动不能绕过真人感私聊许可回答用户。
- `character-phone-store.js:loadCharacterPhoneAutoSettings` 独立保存自动日程权限；不再从真人感开关推断授权。`character-activity-runtime.js` 以活动渠道许可、暂停与额度执行手机等活动。

应该移植的是这些消息身份、许可、批次、取消和上下文边界，复用糯米机现有生成链路；不搬入第二套用户私聊调度器或整套 APK 存储结构。

## 尚未完成、会影响移植的地方

1. **私聊仍有两路自动授权。** `shouldAutoReplyToUser` 是真人感与普通自动回复的 OR；仅关闭真人感仍可能自动回复。开关也没有串起所有在途生成停止机制。此前清理没有声称修复这点。
2. **当前忙碌门禁与参考输入结束模式不一致。** `realPersonReplyReadiness` 的 sleep 阻止回复、冷对话 busy 等待空闲。若原样保留，可能仍需要用户等日程结束或手动按回复；必须按明确模式适配，不能把日程计划当作当前硬离线事实。
3. **“真人感关闭”目前不是所有自动 API 的总暂停。** 自动日程、手机后台和学习室自动陪伴独立存在。最终需清楚区分真人感派生请求与另行授权的自动业务；至少用户私聊及其派生自然行为必须完整停止。不能偷偷扩大授权，或宣称一个开关已经覆盖全部后台 API。
4. **原版自主排程与新增每日联系会重叠。** 只挪走每日 autowake 仍可能由原版聊天工具安排自然联系。需要按动机/来源标记和授权控制；明确委托不应被真人感关闭误取消。现有数据无法证明来源时保留并提示，不猜测批量删除。
5. **不能把双开关简单改成真人感单开关。** 当前自然联系要求真人感和 2.0 都开启；直接去掉 2.0 条件会让只开真人感的用户突然获得后台付费行为。先处理旧任务、明确授权，再切换执行方。
6. **上下文要按事实等级处理。** 日程计划、确认发生的生活事件、学习室真实记录和模型生成的手机故事不能互相证明事实；尤其不能用自动生成的一条手机消息反复激活新的私聊。

## 对前两轮清理的复核

- 搜索未发现退役 `proactivePushConfig`、独立 `worker/proactive-push`、旧节奏设置面板/随机等待器的有效源码引用；保留兼容清理和历史文档不算恢复发送入口。
- `ensureAutonomyWakes` 的生产调用集中在 `amsgAutonomyBootstrap`，聊天页不再另建同一轮维护；OS 层仍处理必要恢复。注意这只是消除重复维护，没有把新增每日联系移出 2.0。
- 旧 1.0 记录在启动/恢复与导入时处理，旧备份不能重新启用发送；取消原生通知失败会保留身份供重试。非常旧、无法证明归属的原生通知可能保留待核对，不能保证已经删除用户设备上的每一条通知，也不能为清干净而误删无关提醒。
- 保留正在使用的注意力算法与旧数据兼容字段是合理的；不应将它们再接成第二套定时回复。
- 本次没有发现需要回滚前两轮清理的证据，但发现了上述尚未迁移的运行边界，以及职责文档对“原版仅提醒”的错误表述。本次修正文档，未提前切换运行权限、删除已有任务或修改 Worker 协议。

## 建议实施次序

先统一用户私聊自动许可与关闭取消；再适配消息批次及输入结束门禁；随后清退新增每日联系/手机搭车绑定并保留结果防护；最后接入独立的自然联系，核对学习室陪伴与手机渠道许可。每一步验证旧任务与新请求不会同时回复、关闭后不再启动真人感请求、迟到结果不会复活，且明确提醒、记忆和用户历史数据继续可用。

# 3D 家园动作复用（开发说明）

> 仅是内部技术分类，不替换用户看到的八个动作菜单分类。新增配置不等于新增动作，不能在加载时预取全部动画。

## 十类基础能力

| 能力键 | 用途 | 已有实现位置 |
| --- | --- | --- |
| `singlePose` | 单人动作、表情、姿态 | `selectedMotions.ts` / `visitor.ts` |
| `handContact` | 手掌对齐、双人接触 | `socialContact.ts` / `pairedHandContact.ts` |
| `bodyContact` | 肩部、身体接触锚点 | `socialContact.ts` / `motionContactProfiles.ts` |
| `armWrap` | 拥抱、手臂环绕、体表避让 | `hugMotion.ts` / `hugArmClearance.ts` |
| `faceContact` | 嘴唇和头颈定位 | `headContactIK.ts` |
| `seatTransition` | 坐下、起身、坐姿切换 | `../seatChange.js` |
| `residentNavigation` | 行走、路径避让 | `../residentNavigation.js` |
| `pairedSync` | 双人共享时间轴、配对动作 | `selectedSocial.ts` |
| `propInteraction` | 手机、杯子等道具 | `socialProps.ts` |

目前只有 **handContact / bodyContact** 的部分既有动作采用了新的声明式 contact profile。
其他八类已有程度不同的专属实现，不代表已经迁移到统一模板。后续每一类都要单独验证再迁移。

## 添加同类动作的原则

1. 从 `selectedMotionCatalog.json` 中已有动作开始，**不要直接修改或覆盖已验证的拥抱动作**。
2. 如果动作符合 `pairedHands`：添加 `motionContactProfiles.ts` 配置，指定渐入/渐出、手指卷曲程度；保持 `pairedHandContact.ts` 的共享目标求解器不变。
3. 如果符合 `bodyTouch`：先验证原素材的骨骼目标和接触范围，再添加 profile；它仍使用原有 legacy 几何追踪，不意味着肩膀自动满足所有碰撞约束。
4. 当接触姿势有特殊需求（掰手腕、托举、头部接触等），**先保留专用逻辑**，不要强行套用通用手掌接口。
5. 动作首次运行可以采样源片段，但**不能在每帧扫描整段动画**。
6. 开发检查：配置测试、原版差异、自检动画加载、Android + Chrome 实际接触表现。没有实机测试时明确标注未验证。

## 第一阶段的既有动作修复（已提交，待实机复测）

- `cmu-18_03`（拉住对方 1）：纠正 IK 先于抬手动画启动而造成的早期伸臂／十字架姿势。动作素材时间起点保留，只延后实际握手目标的介入。
- `cmu-20_12`（低位击掌后走开）：素材双手最接近于 sourceTime 约 .8–1.1 秒；播放器额外延后素材启动 .6 秒，因此对应的手掌接触应处于 actionTime 约 1.4–1.7 秒，而不是原版 actionTime .1–.65 秒。
- `../residentSeparation.js`：在动作结束、起身及平常站立期间检测占位重叠，让可移动的角色逐帧退让。座位和起身中的角色固定，优先让自由站立的 Char 退开。
- `../editor.js`：仅在非双人互动状态执行人物保护壳，尊重家具导航空间，缓存短时间的房间地图。已验证的站立拥抱 `hugMotion.ts`、`hugArmClearance.ts` 未修改。

注意：纯逻辑检查已通过，完整构建／Android 画面动作仍需验证。保护壳是轻量水平碰撞代理，不是精确 SkinnedMesh 连续物理碰撞；若附近没有安全位置，不会强制瞬移穿越家具。

**性能说明**：本阶段没有增加新的动画资源、骨骼或物理引擎。共享手对第一次识别只插值五个时间点 × 两个演员，共 10 次采样；之后 clip 命中缓存。代码复用不等于动画包自动变小，不能据此宣称有确定的 APK 缩小比例。


## 第二阶段：轻量约束调度（代码已接入，画面待测）

- 新增 `motionConstraintPipeline.ts`：预先配置 post-pose 阶段顺序，不在逐帧执行时排序或分配回调。
- 动作本身的 **基础动画采样与应用仍由 `selectedSocial.ts` 负责**。第二阶段约束调度从基础姿态完成后才开始。
- 当前只启用 `cmu-20_10` 的阶段表：**身体位置修正 → 头部安全距离 → 配对手掌 IK → 表情与道具等结束处理**。
- `cmu-20_10` 继续使用第一阶段 `applyPairedHandContact` 和缓存的求解器／手掌对。手指卷曲在现有手掌 IK 内执行，未额外插入每帧手指阶段。
- 所有其他动作仍执行原有阶段顺序，未迁移抱、亲吻、掰手腕、坐姿、托举等实现。其它动作只因抽出原有 root/head 方法而改变函数组织，没有改变操作条件与参数。
- 启动动作时一次选定固定顺序；结束、取消时停用。阶段回调每个场景只创建一次，并复用帧参数对象。
- `motionConstraintPipeline.test.ts`：检查接入白名单、停用、阶段顺序和动作自定义顺序；可用 `pnpm vitest run apps/room3d/chibi/motionConstraintPipeline.test.ts` 验证。
- 保留 `palmContactReport` 作为按需诊断接口，默认不每帧测量接触误差（避免 Android 额外矩阵计算与对象分配）。
- **未验证项**：完整仓库构建、Android Chrome 实机双人接触、不同身高接触距离。不能以纯代码自检替代画面验证；接入范围在实机验证通过前不扩大。

## 起身与走近：最小防穿模修正

- 被动角色保护圈采用与行走检测接近的 0.60 单位，每帧最多移动 0.045 单位，避免原先 0.82–1.15 单位范围内的持续大幅退让。
- 不再额外超出目标距离；角色正行走、起身或执行主动让位时不受被动推开逻辑干扰。
- 自主起身时，前方有人仅做最多 0.30 单位的小步避让。空间不足就不开始起身，不把人横向挪到固定的 0.95 单位外。
- 此处保留简单水平碰撞代理，不引入新物理引擎；完整视觉效果仍需 Android Chrome 复测。

## 第三阶段：面部接触点公共接口（已创建，未改亲吻动作）

- 新增 `faceContactProfiles.ts`：可配置嘴唇、额头、鼻尖及左右脸颊的接触锚点；预设额头贴靠、额头吻、两侧脸颊吻和碰鼻尖（仅底层配方，不在 UI 里增加动作）。
- 嘴唇始终调用原有 `headContactIK.ts` 的 `lipWorld`，**完全保留已有亲吻 IK、身高适配与头部效果**。
- 额头、鼻尖与脸颊接触点按空白素体的原始头部坐标推导，使用当前身高／头围变形参数；局部锚点采用 WeakMap 按 rig 缓存，头部姿势和位置仍实时跟随。
- 可按需调用 `faceContactError` 和 `faceContactEnvelope`，默认不放到游戏每帧循环。
- 新增 `faceContactProfiles.test.ts` 覆盖嘴唇回归、头部旋转、身高/头大小、左右脸颊与配置渐入渐出。
- **尚未连接任何已有动作**，也不声称新锚点与头部渲染表面已经达到真实亲吻接触的精度。Android 实机检验之后再决定是否迁移动作。
